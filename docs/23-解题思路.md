## 〇 一页看完

**题面**：搭建监测 AI 发展的追踪体系——自定分析角度、数据源、更新频率、展现方式，讲清逻辑，标注 AI 做什么、人做什么。

**一句话答案**：不是做一个「会写 AI 研报」的东西，而是一张**从持仓票向上游反推、每条边过验证、每个数可溯源、每个判断有主的因果图**：供给侧是 AI 发展七维 + 前沿雷达，需求侧是 13F 持仓，交点是边（六类 × 跳数 × 三层验证），节点是指标（只存定义，值在四类事实表），治理是来源总账 × 假设台账，呈现是日历式看板 + 蝴蝶结 + 信号表。

**框架**

```
供给侧 · AI 发展七维 D1–D7 + 第四类前沿雷达（topic-driven）
   │  节点 = metric_registry（R，只存定义）；值 = fct_quant / event / opinion / frontier（+ 通用元数据：来源 / P 级 / 知悉时间 / 快照 / 锚点）
   ▼
边 = edge_registry（E）：六类边 × 跳数 × T1 可回测 / T2 结构成立 / T3 方向级；机制 + 证据（由库生成）
   │  打分：节点五因子 r/e/l/s/φ × 系数（全部登记为假设，只排序）→ 可交易度 / 预警度 → 按票归一权重
   ▼
需求侧 · 13F 持仓（NBIS 51% / RBRK 30% / FCEL 7% / 尾仓 8 只；非 AI 仓位只留权重）

治理：来源总账（P1–P5 × 可访问性 × 复验状态）× 假设台账（状态机 + 🟠 闸）× 判断表（owner / status）× 字段级改库账
呈现：日历式主视图（实测 / 预期 / 上期）· 信号表（链状态 / 本周动了什么 / 预警 / 领先读）· 蝴蝶结按需 · 整页下钻
```
