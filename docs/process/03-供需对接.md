# 供需对接 · AI 节点 × 持仓 ticker

> **为什么这么做** — 供给侧全景(①)和指标体系(②)各就位后,要把它们**接起来**:AI 发展节点(供给)怎么连到基金的持仓票(需求),连成一张可推理的图。
> **思路** — 先用"重合"决定深挖谁(AI 六层 × 持仓找交集),再用"一条 thesis 两端读"的对账范式把供给读与需求读接成交叉验证。
> **目标** — 把散点的监测对象与持仓票,变成一张**有向图 + 一套对账逻辑**;并选出最能演示方法论的深度样板(NBIS)。

---

## 一、先找重合:决定深挖谁

拿供给侧全景(六层价值栈)叠 2026Q2 13F 持仓找交集:

| 持仓 | 层 | 供给侧节点 | 是否深挖 |
|---|---|---|---|
| NBIS 51% | L2 neocloud | 光互连 / 电力 / neocloud 容量 + 前沿 lab 需求 | ★ 主样板(两端都全) |
| RBRK 30% | L4 数据安全 | 企业 AI adoption / 数据治理 | ★ 需求扩散代理 |
| FCEL 7% | L1 电力 | 数据中心电力约束 | 能源约束代理 |
| STAA 8% | 医疗 | 追不到任何 AI 节点 | 出 AI scope(留作方法论样板) |
| 尾仓 | L1 | 存储 / 光 / 加速器 | 算力 beta tracker |

**结论**:这本 96% 的书高度集中在 **L1–L2 算力瓶颈 + 一只 L4 AI-adoption SaaS(RBRK)**。里面**没有纯"研究前沿 / 创业一级 / 人才资本驱动"的票**——所以"AI 侧进展读"不是再找一只成熟票,而是**把早期信号层作为同一条 thesis 的需求端读**,而且它天然锚在 NBIS 自己的客户上。

---

## 二、对账范式:一条 thesis,两端读

选定 NBIS 作主样板后,核心洞见是:一条 thesis(AI 算力周期)有天然两端,用两套**独立数据、独立失败模式**读同一件事。

| | 供给端读 | 需求端读 |
|---|---|---|
| 锚 | NBIS 本体 + 光模块供应链 | NBIS 客户 + 前沿 AI 生态 |
| 层 | 成熟层(量价 + 执行) | 早期信号层(事件 + 前沿 + 人才资本) |
| 答什么 | 算力**在建多少** | 算力需求**真不真、续不续** |
| 可得性 | 可回测、进 nowcast | 给方向 / 预警,不直接下注 |

**对账逻辑(最能打的一点)**:
- **同向**(供给猛建 + AI 侧融资 / 进展 / 人才都在涌)= 周期健康、高信念 → 支持加仓。
- **背离**(供给端还在猛建 / 囤 GPU,但 AI 侧融资转冷、进展停滞、人才回流大厂)= **neocloud 泡沫 / 循环融资预警**(NVIDIA–CoreWeave–Nebius 循环 GPU 融资、被称 "WeWork 2.0")→ 减仓 / 关注做空侧。

这条背离信号直接命中 NBIS 的核心分析点(需求持续性 / 客户质量),是卖方分析师一般**不做**的交叉验证——**差异化就在这里**。

---

## 三、对接产出:有向图 + 两个 schema 补丁

把重合与对账落成结构:

- **有向图**:节点 = { AI 供给节点 } ∪ { 持仓 ticker },边 = 传导关系(下一步 ⑤ 细化成六类边 E1–E6)。呈现用**蝴蝶结**(供给左 / 票中 / 需求右)。
- **两个 schema 补丁**在此被真实用例逼出来:
  - `map_path`:AI 进展 → 推理需求 → NBIS 的**间接传导链**(需求端多跳,必须显式记链)。
  - `lead_time_est`:一级资本流**领先 backlog 数季度**(固有领先性要单独建模)。

**样板定案**:以 "NBIS 供给读 ⟷ AI 侧需求读" 这对互补作深度样板——既有真数、又演示两轴互补、又切中 NBIS 真实风险。把 NBIS 从"单只票读"升级成**"一条 thesis 两端对账"**。
