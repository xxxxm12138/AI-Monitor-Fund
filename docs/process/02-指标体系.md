# 指标体系 · 数据类型四分类与字段规范

> **为什么这么做** — 监测对象定了(见 ① 供给侧),但不同数据天生不同:量价能回归、事件要建图、观点要分级、前沿要聚类。一把抓的 schema 会又乱又不可管。
> **思路** — 先立"数据类型四分类"当钥匙,让指标体系、字段、载体、执行路径、数据源**全部从它派生**;每条记录再强制套一层通用元数据。
> **目标** — 一套**逻辑层次天然清晰、可追踪、可管理**的指标体系,把 ① 的监测对象变成可计算、可落库的指标。

---

## 〇、一条主线

不同数据类天生不同,所以先立**数据类型分类**当钥匙,让指标体系、字段、载体、执行路径、数据源都从它派生——逻辑层次天然清晰,也天然可追踪、可管理。四类之外,每条记录再强制套一层**通用元数据**(§二),这是"可追踪 / 可管理"的答案。

---

## 一、数据类型四分类(组织一切的钥匙)

| # | 数据类 | 内容例 | 结构特性 | 存储形式 | 更新频率 | 处理 | 信号角色 |
|---|---|---|---|---|---|---|---|
| **1 量价 / 时序** | 海关、capex、光模块出货、DRAM 价、GPU 租赁价、benchmark 分 | 数值、带时间戳、**可回归可回测** | 时序表(带 as-of 快照) | 定频(日 / 月 / 季) | 确定性代码清洗 + point-in-time + 回归 | 预测变量 |
| **2 实体事件 / 动态** | 融资、新公司、人才流动、产品发布、订单、监管获批 | 离散事件、有主体与关系、**非规则时间** | 事件表 / 实体-关系图 | 事件驱动 | LLM 抽 who-did-what + 实体对齐(人复核) | 预测变量 + regime / 预警 |
| **3 观点 / 表述** | 电话会措辞、卖方 preview、专家访谈、指引、政策情绪 | 非结构化文本、有发言人、**有立场 / 强度、需分级** | 信号台账(codebook 抽取) | 事件驱动 | LLM 按 codebook 抽取分级 + judge + 人标锚点 | 预期基准 / 风险状态 |
| **4 前沿 / 知识** | 论文、benchmark、开源模型、技术博客 | 海量文本、主题演化、**需计量与聚类** | 文献库 + 主题时序 | 高频流(日) | LLM 主题聚类 / 趋势检测(量大必须 AI) | 仲裁 / 方向(早期信号层) |

**为什么这么分**:决定 schema 与处理的不是"内容讲什么",而是"**结构长什么样**"——量价是规则时序(可回归)、事件是离散关系(可建图)、观点是带发言人的分级文本(需 codebook)、前沿是海量需聚类的知识流。四类的处理管线、AI / 人比例、能不能进回归,本质不同——所以字段和载体必须分类定义,不能一把抓。

---

## 二、字段规范

### 2.1 通用元数据层(每条记录都强制带 —— "可追踪 / 可管理"的直接答案)

- **溯源**:record_id · source_id · source_url · anchor(原文锚点 / 页码 / 时间码)· snapshot_id(原始快照)· **knowledge_time(as-of,何时可知,回测生命线)** · ingest_time
- **口径**:口径定义 · unit · currency · frequency · 口径_version
- **质量**:owner(AI 生成 / 分析师复核 / 数据团队)· confidence · code_score · judge_score · status · model_version / codebook_version
- **关联**:entity_id · ticker_map(影响哪只票 + 关系)· layer · track · maturity · data_class · signal_role · valuable_score

**一句话**:溯源保证可追踪,口径保证可对齐,质量保证可信可分工,关联保证能落到 ticker 和赛道。**任何一条数据缺这层就不进资产库。**

### 2.2 每类专有 payload(在通用层之上)

- **类1 量价**:period · value · yoy / qoq · revision_flag(初值 / 修订)
- **类2 事件**:event_type · subject_entity · object_entity · relation · amount · round · event_date
- **类3 观点**:variable · speaker · speaker_role · level · strength · direction · anchor_quote
- **类4 前沿**:doc_id · topic_cluster · method · benchmark · score · institution · citation_velocity

### 2.3 逻辑分层数据模型

- **实体层(entity master)**:公司 / 机构 / 人 / 赛道主数据 + 映射表(一级公司 ↔ 公开 ticker、别名、层级、成熟度、中 / 海外)。所有数据挂到 entity_id。
- **指标层(metric registry,唯一真源 R)**:每指标一行元数据(名称、层、data_class、signal_role、源、频率、lead_time、口径、owner、valuable、状态、last_validated)。**改指标只动 registry。**
- **信号层**:指标经处理后的三态(看多 / 看空 / 无信号)+ 置信 + 原文锚点。
- **呈现层**:按用户(研究员 / PM)组织的视图(指标树 / watchlist / 情绪 / 热力)。

---

## 三、呈现载体

**载体栈(复用已有工具,不新造)**:raw 湖(DuckDB / 对象存储快照)→ 资产层(Postgres / Tiger,按 knowledge_time 索引,存 registry + fct 表)→ 处理 trace(Langfuse)→ 呈现(panel 指标树)。

- **可追踪** = knowledge_time + snapshot_id + trace 锚点贯穿全链,任一信号可回溯到原始快照与处理步骤。
- **可管理** = metric_registry 单一真源 + 受控词表(layer / track / data_class / signal_role / owner)+ 版本化(口径 / codebook / model)。
- **呈现形式按数据类**:类1 → 时序图 + nowcast 三态;类2 → 事件流 + 关系图 + watchlist;类3 → 分级表 + 情绪指数 + 缺席检测;类4 → 主题热力 + 斜率曲线。统一挂在指标树上(L 层 × 赛道为骨),节点带人机分工标注,可下钻「字段 / 处理 / trace」。

## 四、执行先后路径(build roadmap · 螺旋:先深核心,再横向)

| Wave | 范围 | 主用数据类 | 产出 |
|---|---|---|---|
| **0 骨架** | 立地基,不填数 | — | 实体主表 + 映射 + registry schema + 四类模板 + 载体空壳 |
| **1 核心成熟层** | L1 / L2 现有 ticker(NBIS / RBRK / FCEL / SUPX / 存储 / 光) | 1 量价 + 3 关键观点 | 第一条可回测 nowcast + 深度样板 |
| **2 同赛道向早期推** | pre-IPO → 更早轮次 → 研究前沿(同赛道) | + 2 事件 + 4 前沿 | 领先信号 + 挑战者预警 + 未来机会种子 |
| **3 相邻赛道** | 产业链上下游 / 相邻 | 全 4 类 | 横向复制 |
| **4 全市场 + 未来机会雷达** | 早期信号层全面铺 | 4 前沿为主 | 通用 AI 雷达 |

**关键**:每 wave 只加**实体行 + 指标行**,不重造 schema / 载体——这就是"复用方法论、可维护、可优化"的具体落点。

## 五、数据源梳理 + 采集优先级(聚焦 L1 / L2 核心)

**数据源清单(节选,按 数据类 × 层)**:

| 数据源 | 类 | 层 / 赛道 | 对应指标 | 频率 / 领先 | 中国侧 |
|---|---|---|---|---|---|

| 中际旭创 / 新易盛月度营收 | 1 | L1 光模块 | 光模块需求 | 月,领先 | ✓ 中国上市 |
| 海关 HS8517 | 1 | L1 | 出口量价 | 月,领先 6–8w | ✓ |
| NBIS 签约 / backlog | 2 + 3 | L2 neocloud | 需求订单 | 事件 | — |
| 数据中心 PPA / 机组订单(FCEL) | 2 | L1 电力 | 电力需求 | 事件 | — |
| 中国 AI 服务器招投标(SUPX) | 2 | L2 服务器 | 订单 / 需求 | 事件 | ✓ |
| arXiv / HuggingFace / benchmark 榜 | 4 | 早期 A | 主题斜率 / 能力拐点 | 日 | 中国 lab / 开源 |
| PitchBook / IT桔子 · 烯牛 | 2 | 早期 B | 赛道资金流 / 挑战者 | 事件 | ✓ 一级 sourcing |

**四条使用路径(每数据类一条 raw → 资产 → 信号 → 呈现)**:
- **类1 量价**:落快照 → 规则清洗 + 单位 / 日历对齐 → 存资产层(带 knowledge_time)→ 固定池同比 + 回归 + point-in-time 回测 → 时序 / 三态。人只定口径。
- **类2 事件**:抓取 → LLM 抽 who-did-what + 实体对齐(人复核首映射)→ 事件表 → 规则聚合 → 事件流 / watchlist / 预警。
- **类3 观点**:落快照 → 按发言人切分 → LLM 按 codebook 抽取分级(带锚点)→ 代码闸门 + judge + 路由人工 → 信号台账。
- **类4 前沿**:高频抓取 → LLM 主题聚类 / 趋势检测 → 主题时序 → 斜率 / 异常检测 → 热力 / watchlist。

**采集优先级(按 valuable = 离 ticker 距离 × 独家性)**:
1. **中国侧、直接驱动核心 ticker 收入、别人拿不到的**(光模块月营收、海关、中国服务器招投标)——最先抓。
2. 近 ticker 但半公开(capex 指引、DRAM 价、GPU 价)——抓,但认知它不独家,靠拼接与中国侧增量取胜。
3. 早期信号层(论文 / 融资 / 人才)——独家性高但离 ticker 远,做 watchlist / 方向,Wave 2 起铺。
