# 映射范式 · 点 · 边 · 权重

> **为什么这么做** — 有向图连起来了(③),但"节点定义清楚"只是名词对了;要能下注,得回答"AI 发展**怎么可计算地、可回测地**传导到一只具体的票"。
> **思路** — 从每只票的核心因子**向上游反推**,数跳数、分六类边,再用一个**映射价值函数**(传导 × 节点质量)给每条链打分、排出重点。
> **目标** — 一套**可复用、可量化**的映射范式:换票只换核心因子与链,七维节点池不变;每条边可验证、可版本化。数据锚 2026Q2 13F。

---

## 一、一张有向图:节点 + 六类边

**节点** = { AI 发展节点(D1–D7 七维全集) } ∪ { 持仓 ticker }。

**边**(传导关系)分六类,每一类回答"AI 发展怎么传到票"的一种机制。从票向上游看,每类边对应一个追问:

| 边 | 含义 | 从票向上游看 = 追问 |
|---|---|---|
| **E1 本体** | 票本身即某 AI 节点的载体 | 这票"是"哪个 AI 发展节点? |
| **E2 供应链上游** | 票依赖的投入 | 它造东西要谁的货?(GPU / HBM / 光 / 电) |
| **E3 下游 / 客户需求** | 票收入被谁的 AI 需求驱动 | 谁买它、那个需求由哪个 AI 节点决定? |
| **E4 竞对 / 替代** | 什么 AI 进展威胁它 | 哪个 AI 节点起来会替代 / 侵蚀它? |
| **E5 主题轮动** | 票随赛道资金 beta 轮动 | 它跟哪个 AI 主题同涨跌? |
| **E6 资金 / 人才流** | 早期要素涌入领先其需求 | 钱 / 人往哪流,领先它的估值 / 需求? |

## 二、跳数的定义 + 逐票链式图

**跳数** = 从"票的收入 / 利润因子"沿经济传导链反推到某 AI 发展节点,所跨过的**因果箭头数**。每一跳 = 一次"因 → 果",且跨一个实体或市场边界(信号在此可能衰减、滞后、被别的因素淹没)。

- **0 跳(E1 本体)**:票本身就是该节点。例:NBIS backlog = D1 neocloud 容量节点。
- **1 跳(E2 / E3 / E4 直接供需)**:一条直接经济关系。例:NBIS 自有电力上电 → NBIS 产能。
- **2+ 跳**:信号要穿过中介才到票。例:模型能力 → 推理需求 → lab 采购 → NBIS。

跳数不是拍脑袋定的,而是**沿商业模式链把箭头数出来的**——先拆出票的核心因子(利润 = 量 × 价 − 成本 里最不稳的那个),再沿链反推。逐票不同,所以必须画链式图。链式图把跳数**显式化、可复核**,这正是它能进价值函数的前提。

**NBIS**(收入因子 = 产能执行 × 需求持续性,收入预合同化):

```
D1 光互连出货      ─①→ 全球 AI 集群在建强度 ─②→ neocloud 扩张 ─③→ NBIS 产能骑乘   [3 跳 · E2 赛道 beta]
D1 NBIS backlog(本体) ────────────────────────────────────────→ NBIS            [0 跳 · E1]
D1 NBIS 自有电力上电 ─①→ NBIS 产能执行(延期 = 收入递延)                          [1 跳 · E2 直接] ★ 关键可观测
D3 前沿 lab 融资    ─①→ lab 算力采购力 ─②→ NBIS 签约 / backlog                    [2 跳 · E3 客户需求]
D5 模型能力进展    ─①→ 推理 / 训练需求 ─②→ lab 算力采购 ─③→ NBIS 用量            [3 跳 · E3]
D7 电力 / 电网政策 ─①→ 数据中心用电审批 ─②→ NBIS 上电节奏                         [2 跳 · regime]
D7 出口管制        ─①→ GPU 供给 / 成本 ─②→ NBIS 产能成本 / 可得                    [2 跳 · regime]
```

**RBRK**(因子 = 订阅 ARR 增速 × NRR,企业 AI-adoption 驱动):

```
D6 企业 AI adoption    ─①→ 企业需备好 / 护住 AI 数据 ─②→ RBRK 订阅需求   [2 跳 · E3]
D2 数据合规 / 版权趋势 ─①→ 企业数据治理预算 ─②→ RBRK 顺风               [2 跳 · E3]
D7 AI 监管 / 数据合规  ─①→ 治理预算 ↑ ─②→ RBRK 需求                     [2 跳 · regime]
D5 AI-native 安全挑战者 / 大厂自带 ─①→ 替代 RBRK                        [1 跳 · E4 竞对] 做空侧
```

**FCEL**(因子 = 数据中心电力订单):

```
D7 能源 / 电网政策 · 核电 · PPA ─①→ 数据中心供电方案 ─②→ FCEL 订单   [2 跳 · regime / E2]
D1 AI 数据中心建设 ─①→ 电力需求 ─②→ FCEL 机会                       [2 跳 · E3 下游]
```

**算力尾仓**(SUPX / SNDK / MU / INTC / CIEN / MRVL / POET / AMD):各 1 跳 · E2 到 D1 的某子节点(存储 / 光 / 加速器 / 整机),本体即算力供应链一环。

## 三、映射价值函数:V = f(传导 T, 节点质量 Q)

只讲"信号怎么走到票"是不够的——还要回答"信号本身值不值"。所以价值函数拆成两组因子:

**① 传导 T(跳数 × 边型)—— 信号怎么到票**
- **领先期 τ**:跳数越多、越靠早期边(E4 / E6 / 到 D5)→ 领先越久。
- **传导确定性 c**:跳数越少、越靠结构化边(E1 / E2 / E3)→ 传导越确定(不易中途被淹)。c 由边的三层验证(见 §七)定,不再拍脑袋。

**② 节点质量 Q(信号本身的固有属性,与跳数无关)—— 信号值不值**
- **可靠性 r**:数据可信 / 口径稳(接来源等级 P1–P5)。
- **独家性 e**:别人拿不拿得到。
- **固有领先性 l**:信号天然领先基本面多久(如一级融资天然领先数季度,与跳数叠加)。
- **可观测性 / 信噪比 s**:可否量化、噪声大不大(arXiv 灌水 = 低 s)。
- **频率 φ**:更新够不够密。

V 落成**两个可用产出**(呼应"早期层管往哪看、成熟层管下多少注"):

| 产出 | 公式(定性) | 高 → 用途 |
|---|---|---|
| **可交易度** | c(传导确定) × r(可靠) × s(可观测) × φ(频率) | 进 nowcast、回测,决定**下多少注** |
| **预警 / 方向度** | τ(领先) × l(固有领先) × e(独家) | 上 watchlist,给**方向 / 预警**,不下注 |

一条映射两产出可都不低(理想),也常一高一低:光模块 = 可交易高 / 预警中;lab 融资 = 预警高 / 可交易低。因子取值先用**高 / 中 / 低(H / M / L)**定性打分,够排序;要精确再回测标定——现阶段不编假精度。

## 四、推导 SOP(任一票可复用)

1. 定层(L1–L6)与商业模式。
2. 拆核心因子(利润 = 量 × 价 − 成本 里最不稳的那个)。
3. 画链式图,沿边向上游追到 AI 节点,数跳。
4. 追竞对边 E4(做空侧)。
5. 每条链标 τ / c(传导)+ r / e / l / s / φ(节点质量)→ 两个 V 产出。
6. 停止规则:数据拿不到 / 不再领先就停。

换票只换核心因子与链,**七维节点池不变**。

## 七、边确定性三层验证:A 是否必然导致 B → edge_registry

节点定义清楚只是"名词对了",**边的确定性才决定这条链是信号还是故事**。每条边落库到 `edge_registry`,`cert_tier` 分三层:

- **T1 可回测边**:两端可观测时序 + 历史够 → lead-lag / Granger / 样本外稳定 → 实测 c + 领先期。例:光互连出货 ↔ hyperscaler capex。
- **T2 结构边**(点太少 / 下游预合同化,不能直接回归)→ 结构论证 + 真值对账 + 敏感性分析。例:lab 融资 → NBIS backlog。
- **T3 方向边**(能力 → 需求、人才 → 赛道):结构上无法证确定 → 只 watchlist,**永不据此定仓位**(不编假精度)。

这把价值函数里的传导确定性 c 从"拍脑袋"升级成**实测 / 评定带 evidence**;每条边可版本化、可复验(`last_validated` + `evidence_ids`)。这也是把整套从"讲得通的故事"变成"经得起回测的资产"的关键一环。

## 八、呈现设计:蝴蝶结布局与编码通道分配

原则(图论 / 信息论):视觉通道有预算,**位置(x / y)解码最准 → 把最重要的维度放到位置上**。据此把"供给 / 需求"从弱通道(颜色)升到强通道(位置),腾出颜色去背最 actionable 的信息:

| 维度 | 视觉通道 | 说明 |
|---|---|---|
| 供给 / 需求(上下游) | x 侧:票居中 · 供给左 · 需求右 | 从颜色升到位置(最强通道) |
| 跳数 | x 离中心距离 | 越远越领先越不确定;与上下游共用 x 轴(一箭双雕) |
| 产出(可交易 / 预警) | 颜色(绿 / 橙) | 腾出的颜色背"怎么用" |
| 确定性 tier | 线型(实 T1 / 长虚 T2 / 点 T3) | 见 §七 |
| 竞对 | 红框 | 做空侧 |
| 政策 regime | 顶部横带 | 横切,不分上下游 |
| 重点 | ★ | |

一眼可读:NBIS 两头夹(供给 + 需求)、RBRK 需求驱动 + 竞对、FCEL 需求 + regime。选型依据 = 未来要展示的维度总数:维度越多,越要把最重要的几个放位置、其余分到线型 / 边框 / 泳道,避免颜色过载。

## 三条给面试官的洞见

1. **范式可复用且可量化**:映射 = 从票向上游沿六类边走,V = f(传导[跳数 × 边型],节点质量[可靠 · 独家 · 领先 · 信噪 · 频率]),落成"可交易度 / 预警度"两个产出;换票只换核心因子与链,七维节点池不变——可维护、可进化。
2. **书的轮动会给范式打分**:E5 主题轮动 = 基金对重点节点的真金投票;我们排的重点若与轮动方向一致,即被市场行为反向验证。
3. **科研重要 ≠ 对我们重要**:能力前沿(D5)对"AI 发展"最本质,但对这本押算力的书,D1 算力 + D7 政策 + D3 资本更直接——懂这个落差,才是"监测 AI 发展"落到"我们的书"的真本事。
