# 20 · 执行路由与校准复盘闭环:系统怎么自进化(2026-09-21)

一个反常识的核心:**执行主体不是静态分配给谁,而是"成熟度阶梯上的当前位置"。路由 = 能力上限 × 校准闸允许的成熟度。所有主体写同一张 `decision_log`,才可比、可复盘、可晋升。**

这是"为后来基建做设计"的自进化核心——系统不止出判断,还**测自己判断**、按证据把判断沿自动化阶梯**升 / 降**、regime 拐点**自动收权回人**。

对应现有 schema:`decision_registry.executor_kind`(rule/human/llm/model)、`.calib_status`(human→shadow→assisted→auto)、`.research_tier`(A/B/C);`decision_log` 六元组;`candidate_pool`;校准闸(🟠闸:未 validated 禁 assisted/auto);Langfuse(llm 的 trace+eval,设计未建)。

---

## 1 · 路由依据:谁做这个判断

依据是任务的属性,不是拍脑袋分工:

| 主体 | 什么时候路由给它 | 11 类里的落位 | provenance(记什么) |
|---|---|---|---|
| **code/rule** | 可形式化、可复算、零边际成本 | 可交易度 c·r·s·φ、跳数、阈值触发、2×2 定位 | `rule_id + git_sha + 输入快照` → 完全可重放 |
| **llm** | 需语义 / 非结构化理解:抽取 / 聚类 / stance | 源分类五元组、顶刊 / blog 主题聚类、证伪闸 stance | `prompt_ver + model_id + Langfuse trace_id + eval 分` |
| **model** | 有基率、可回测的窄预测 | lead-lag 预测器(攒够 N 后)、传导确定性打分 | `model_id + ver + 特征向量 + 训练截止` |
| **human** | 奈特不确定 / 不可逆 / 无基率 / 需问责 | 反身性、regime 拐点、影响力闸终判、潜在标的进出 | `analyst(A–D)+ note + 耗时` |

**路由规则:`运行档 = min(能力上限, 校准闸允许成熟度)`。** 能力定天花板(反身性判断天花板就是 human,再多数据也不该自动化);`calib_status` = 它凭成绩爬到了第几级。同一类判断,能力不变,档位随校准动。

---

## 2 · 怎么统计

切片维度固定 `type × executor × calib_status × regime`,滚动窗(校准非平稳):

| 量 | 指标 | 治什么 |
|---|---|---|
| 校准 | Brier / ECE / 可靠性曲线(说 .9 真命中 9 成?) | confidence 名不副实 |
| 区分度 | IC / rank-IC / 命中率 / lead 准确度 | 分高是否真预测得准 |
| 抽取质量 | P/R/F1 vs 人标(Langfuse eval) | LLM 抽错 / 幻觉 |
| **价值归因** | **P&L attribution / 是否改变了决策** | **校准但没用(已 priced)** |
| 成本 | 人分钟 / token$ / ms | 经济路由 |
| 逃逸率 | escalation / OOD 比例上升 | 漂移早警 |

两个关键:**晋升信号 = 同一 `state_anchor` 上 shadow 成绩 ≥ acting**(影子悄悄比人准了才够格晋升);**北极星 = P&L 归因**——校准是必要非充分,校准完美但只预测已 priced 的判断 IC 高却零 edge,只有归因抓得出。

## 3 · 每层怎么记录(供复盘)

统一记录 = `decision_log` 六元组(state_anchor / candidates / choice / confidence / basis / outcome),再挂各主体 provenance(见 §1)。三条铁律:

1. **事前登记**:`state_anchor + candidates(预期)` 必须在 `outcome` 之前落库。否则"意外"和校准全是事后诸葛——这是 `decision_log` 存在的全部理由。
2. **影子日志**:即便这类判断现在跑 human,LLM / model 也在**同一 anchor 上静默预测并记录**。没有影子历史就没有晋升依据——这是自进化的燃料。
3. **反事实**:`candidate_pool` 里 `rejected` 的行也要跟踪结果。只从"做了的选择"学 = 选择偏差,拒掉的才是对照组。

---

## 4 · 复盘优化链路:双控制器闭环

不是"记了回头看看",是个双环控制器:

![校准复盘双控制器闭环](../assets/readme/calibration-loop.svg)

- **内环**优化每个主体的质量:code 改公式 / 阈值(版本化 diff)、llm 改 prompt / few-shot / 把低分 case 喂进 eval、model 重训(有基率了)、human 给反馈 + 更新 checklist。
- **外环**优化路由本身:校准闸按影子成绩把判断沿阶梯**晋升 / 降级**,改的是 `executor_kind`。
- **regime-aware**:regime 一变,auto 判断自动**隔离回 shadow**(基率破了)——这正是最该收权回人的时刻。
- 节奏 = 各判断的 **outcome horizon**(lead 预测周级,regime 季级)。

---

## 5 · 陷阱(数据科学)

1. **非平稳**:别把不同 regime 的样本混池;滚动窗 + regime 切片。
2. **小 N 上限**:regime 拐点这类一辈子攒不够样本 → **永远该留 human**,对它测"过程质量"而非命中率,别硬推上阶梯。
3. **Lookahead**:`outcome` 时间戳必须严格晚于 `state_anchor`。
4. **选择偏差**:只统计做了的选择会高估自己 → 用 `candidate_pool.rejected` 做反事实对照。
5. **Goodhart**:指标一当晋升闸,LLM prompt 会朝 eval 过拟合 → 留 held-out / 对抗 eval + auto 也人抽审。
