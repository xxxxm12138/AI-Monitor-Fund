# 面板形式再设计 · 图不该做主视图

**日期** 2026-09-20 ｜ **性质** 设计推演(用户/JTBD 视角)｜ **触发** D:现面板不直观,图形式是否不适合 ｜ **结论** 图降为下钻,主视图改**优先级分流 feed**

---

## 一 先定用户与 JTBD(形式必须服从这个)

- **用户**:成长股基金的**研究员 + PM**(港股/美股),不是数据岗。
- **要雇这个面板干的活(JTBD)**:早上/盘中快速回答三问——**"AI 发展里什么变了 → 对我持仓意味着什么 → 下一步看什么/做什么"**。
- **工作节奏(我们自己的 JEV 洞见)**:**开枪低频、瞄准高频**。研究员一天做几十上百次"这条值不值得再看一眼"的**分流(triage)**,一年真开枪个位数次。→ 他要的是**分流器**,不是拓扑探索器。
- **五个决策时刻**(E19/N4):持有中 · 财报前 · 风险监控 · 证伪 · 轮动。面板每一屏都应服务其中之一。

## 二 图(节点-连线)为什么不适合做主视图(诚实批评)

节点图擅长表达**结构**(什么连什么,一次性讲清"AI 怎么打到 NBIS"的方法论);但对**日用工作流**是错的形式:

1. **不排序**:研究员要按重要性 triage,图天生没有优先级/顺序——一屏节点一样大,不知先看谁。
2. **看不出"变化"**:图是静态拓扑,回答不了"**今天什么动了**"——而这正是每天第一问。
3. **规模即 hairball**:36 链就已经挤成一团;票和信号一多,连线交叉到不可读。
4. **认知负担高**:用眼睛追线 ≫ 扫一列表。研究员没时间在图里找。

**一句话**:图回答"为什么(结构)",研究员每天问的是"什么变了、该干嘛(状态+动作)"。用错了。

## 三 竞品都用什么形式(印证:表/feed 为主,图为下钻)

| 竞品 | 主视图形式 | 图在哪 |
|---|---|---|
| TradingView / Bloomberg 经济日历 | **时间序的行**(什么时候来) | 无(或独立图表) |
| TickerTrends(最像我们) | **一行一 KPI 的分流表**(估计/共识/Δ/置信/修正 sparkline,可排序) | 无;下钻看 source 信号 |
| Daloopa / Visible Alpha | **表格 + 逐格下钻** | 无 |
| AlphaSense | 搜索 + 文档 feed + 仪表盘 | 无 |
| DataHub / OpenMetadata | 搜索 + 列表为主 | **血缘图存在,但是下钻**,不是打开就看到 |

**规律很硬**:没有一家专业金融/数据工具把节点-连线图当日用主视图。**表格/列表/feed 做主 surface,图只在"解释某条连接"时下钻出现。** 连数据目录(它的核心就是血缘图)都把图放在下钻层。

## 四 该用的形式:优先级分流 feed 为主,图为下钻

- **主视图 = 优先级分流 feed/表**,按**决策时刻**组织(不是按拓扑),每行一条"值得看一眼的东西",可排序、显变化。
- **图降为下钻**:点一条信号/一只票 → 抽屉里出**路径卡 + mini 传播图**("这条 AI 发展经哪条因果链打到 NBIS")。图在"解释因果"时才出现,不是开屏主区。

> 这其实是**回到 E28 的原判**(日历式 > K线/节点图,因为"监测的是事件流不是价格,图只在看影响时需要")。中间 graph-primary 是弯路——把"给面试官讲方法论的展示图"误当成"研究员日用主视图"。两者是两个东西:**方法论展示图保留**(讲清逻辑,面试/汇报用),**日用主视图改 feed**。

## 五 主视图放什么(extra-value 信息架构)

顶部**开枪 vs 瞄准抬头**(2×2:act 现在动 / watch 观察 / priced 已反映 / ignore),把当天过闸信号分流。

**① 今日分流(主 feed,回答"什么变了")** —— 每行一条过闸信号:
`是什么 · 何时可知 · 证伪级 · 影响力(渠道→落点)· 打到哪只持仓 · 方向 · 2×2 格 · 下一验证点`
→ 只显过两闸的(6 外溢);未过闸的进"前沿雷达"次级 tab,不占主屏。

**② 持仓 thesis(回答"对我意味着什么")** —— 每票一行:
`thesis regime(信念/观察/泡沫)· 本周什么动了 · 量级 nowcast KPI 三值(Actual/Forecast/Prior,等数据)· falsifier · 下一数据点`

**③ 前沿雷达**(未过闸的方向信号,给"往哪看"不给下注)· **④ 映射图**(方法论展示图,即现在这张传播图,挪到这里)。

**下钻抽屉**:点任意行 → 信号卡/节点档案/路径卡 + **mini 传播图**(图在此出现)。

## 六 布局

```
顶栏:今日分流 | 持仓 thesis | 前沿雷达 | 映射图(方法论)      [as-of · 主题]
─────────────────────────────────────────────
[2×2 抬头:act N · watch N · priced N · ignore N]
─────────────────────────────────────────────
主区 = 分流表(可排序,一行一条)          │  抽屉:选中行的卡
 信号/票 · 变化 · 影响 · 落点 · 方向 · 下一点 │  (信号/路径/节点 + mini 图)
```

图只在两处出现:**"映射图" tab(方法论)** 和 **抽屉里的 mini-graph(下钻某条)**;主区永远是可扫、可排、显变化的**表**。

## 八 身份表达:两层含义,不同设计动作(D 已认可方向)

面板要同时喊出两件事,分开做:
**(A) 监测对象 = AI 发展本身(扣题,别读成选股工具)**:① 开屏 hero 先"AI 发展态势"再"组合影响";② 常驻「AI 发展态势」记分牌(D1–D7 七维当前态,不挂票);③ AI 前沿动态一等 tab;④ 视觉箭头永远 AI → 持仓。
**(B) 方法 = AI-driven(JEV + 分工)**:① 四算子可见(每条信号显示 REPRESENT→PROPOSE→PREDICT→SELECT 走过);② A/B/C/D 分工 chip 常驻(题目硬要求标 AI/人);③ 压缩式决策行(每行一个分流结论 + 投资含义,理由下钻)——面板形式本身即 JEV 证明;④ 诚实置信/来源等级;⑤ "怎么算出来的"下钻 = 可审计推理链。
**Signature 横带**(见 §九 专业版):AI 发展态势 → 验证与重要性筛选 → 组合影响,一条带说清 A+B。
